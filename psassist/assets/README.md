# assets/ — テンプレート資産

## bubbles.psd （ユーザー作成・必須）

JSX がバブルを置く時の **複製元**。ExtendScript にはカスタムシェイプを名前指定で
配置する API が無いため、このPSDからレイヤーを `duplicate()` して持ち込む方式を取る。
ベクターシェイプなので、複製後の拡大縮小・反転はすべて無劣化。

### 置き場所は1箇所だけ（2026-09-02・S4）

**中身はチャンネルによらず使う汎用テンプレート**（丸/四角/雲/スパイクという形の語彙は
どのチャンネルでも通用する。チャンネル固有なのは「どの話者にどの形を既定で使うか」
という対応表＝`speaker_defaults.json`の方）。ユーザー自作・非公開のため公開リポには
乗らず（`scripts/public-manifest.json`の許可リストに`assets/bubbles.psd`自体は無い）、
チャンネルを増やすたびに**コピーし忘れて同じ失敗を繰り返していた**
（`memory/bubbles-psd-critical-asset-sync-gap`）。

対処は「チャンネルごとにコピーする」ではなく **実体を1箇所だけに保ち、各チャンネルの
`.env`の`PSA_BUBBLES_PSD`にその1箇所の絶対パスを指させる**こと。`plan_builder.Paths.from_env()`
はもともとこの絶対パス指定を想定した作り（`DEFAULT_BUBBLES_PSD`は未設定時のフォールバック
に過ぎない）なので、コード変更は不要。**新しいチャンネルを増やす時は、ファイルをコピーせず
`.env`の`PSA_BUBBLES_PSD`に既存の1箇所（通常は開発チェックアウト）を指定するだけでよい。**
起動時に`host_worker.py`が実在を確認し、無ければ警告する（`memory`参照・実装は
`Docs/AROLL_PSASSIST_REFACTOR_PLAN.md` S4）。

### ⚠️ 塗り・線は「完成品の状態」で作ること

レイヤー複製は塗り・線・レイヤースタイルをそのまま引き継ぐ。つまり
**bubbles.psd の見た目がそのまま出力の見た目になる**。線幅や白の塗りを
最終形で入れておくこと。逆に言えば、後で全パネルの線を太くしたくなったら
bubbles.psd を直して再生成すればよい。

### なぜ反転版を入れないのか

既存129枚のうち40枚のシェイプを実測した結果:

- **尻尾は 32/33 (97%) が下向き** → 上下反転はほぼ発生しない
- **尻尾の左右は、バブルの画面位置から予測できない**
  （バブルが右にある時、左寄り6 / 右寄り6 と完全に半々）

つまり反転は「規則で決まるもの」ではなく、キャラの顔の位置ごとの判断。
一方で **ExtendScript での反転は1行**（`layer.resize(-100, 100, ...)`）で
無劣化。したがって:

- 資産は **正位置9枚だけ**（反転版まで作ると 9×4 = 36枚になり、作る手間が
  増えるだけで得るものが無い）
- 反転は **プラン側のパラメータ**（`flip_h` / `flip_v`）として持ち、JSX が適用
- 既定値は自動で入れ、違えば MCP で1コール変更（`rebuild_panel(45, flip_h=true)`）

「半自動＝ユーザーが手で直す」ではなく「**既定を置いて、直すのを一瞬にする**」
という方針。手で反転する作業自体を無くす。

## background_overrides.json （ユーザーの自己申告）

**機械では測れない判断をここに置く。** 話数フォルダに置くと片付けた時に消えるため、
残す場所を分ける。

| ファイル | 置き場所 | 読み手 | 何を記録するか |
|---|---|---|---|
| `background_overrides.json` | **repo**（ここ） | psassist（ホスト常駐） | 1枚ごとの制約（`banned` / `allowed_shots`） |
| `character_overrides.json` | **`shared/characters/`** | scrapping-agent（コンテナ） | 閾値（`thresholds`）+ 1枚ごとの制約（`overrides`）+ **2枚の関係**（`pair_judgments`） |

⚠️ **置き場所が違うのは読み手が違うから。** コンテナには `./shared:/shared` しか
マウントされていないので、repo の `assets/` はコンテナから見えない。
背景版が repo に居られるのは、読み手の psassist がホスト常駐でリポジトリを直接
見られるため。「手作業だから repo」ではなく「**誰が読むか**」で決まる。

キャラ側に `pair_judgments` があるのは、「ワンパターンに見える」が**1枚では表せない**ため。
実際 2026-08-25 の検証で閾値を 0.144 → 0.073 に動かしたのはペア判定80件だった。

⚠️ `pair_judgments` の `context`（`isolated` / `in_episode`）を落とさないこと。
**同じ距離でも文脈で判定が変わる**のが最大の発見で、文脈を落とすと較正データが嘘になる。

更新は `psassist/scripts/build_overrides.py`（判定CSVから集約）。
設計の本籍は `psassist/Docs/CHARACTER_CUTOUT_PLAN.md` §11。

## `speaker_defaults.json`（話者ごとの既定バブル・任意）

話者名 → バブル形状と左右の既定値。**チャンネル固有のデータなので配布物には入れない**
（`background_overrides.json` と同じ扱い）。

```json
{
  "speakers": {
    "<話者名>": {
      "bubble_key": "rect_a", "side": "right", "note": "",
      "question_bubble_key": "cloud_a", "exclaim_bubble_key": "spike_a"
    }
  }
}
```

`bubble_key` は `spec.BUBBLES` のキー（`rect_a` / `round_a` / `cloud_a` / `spike_a` …）。
知らないキーは黙って捨てられ、既定へ落ちる。

⚠️ **無くても動く。** 未知の話者は `spec.FALLBACK_DEFAULT` に落ち、`UNKNOWN_SPEAKER`
警告が出るだけ。しかも**左右は在庫の`mask`/`mask_stats`があればそちらが優先される**
（実測82%で、話者別の最頻値64%より正確）。効くのはマスクが無い行の左右と、
バブル形状の既定値（記号による上書きが無い行）だけ。

⚠️ **このファイルが無い環境では全行が`rect_a`・全行`UNKNOWN_SPEAKER`になる。**
「無くても動く」は安全に縮退するという意味で、「無くてもチャンネルらしい見た目になる」
という意味ではない。新しい環境で組版を始める前に実在を確認すること
（`bubbles.psd`と同じ同期の穴。`Docs/AROLL_PSASSIST_REFACTOR_PLAN.md` S4参照）。

### 形状は感情推定では当てられない・記号なら別（2026-09-02新規・S3）

話者固定の`bubble_key`（形状の初期値）は**そもそも当てられない** ── 129枚の実測で、
emotion を使っても約60%にしかならず最頻値の決め打ち47%と大差なかった。当てにいかず、
既定を置いて人が直す方針（`psd-layout-has-no-rule`）は変えていない。

一方 `question_bubble_key`/`exclaim_bubble_key`（任意）は**LLMの感情推定を経由しない**、
文中の記号（？/！）という決定的な信号で行ごとに上書きする。「材料を増やせば予測できる
ようになるものもある」（`psd-layout-has-no-rule`の左右判定64%→82%と同じ理屈）を
試したもの。**元の129枚データは既に整理済みで現存しないため実測での再検証はできていない**
──`bubble_key_for()`のdocstring参照。設定しない話者（例: 常に四角の話者）は
これまでどおり`bubble_key`固定のまま（後方互換）。優先順位は！＞？＞既定。
